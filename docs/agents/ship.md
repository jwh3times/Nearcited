# Ship

## Fast checks

Together they cover the static gates of every required check and its unit suites. All need
`pnpm install`; where `pnpm` is not on `PATH`, `npx pnpm@10.28.0 <args>` (see
`docs/agents/workspace.md`).

- repo root: `pnpm check` (**Lint, typecheck, test, build**: Biome `lint`, `typecheck`, every
  package's `test` including the row-level security tests, `test:scripts`, `build`; well under a
  minute), a Biome failure fixed by `pnpm format`
- repo root, only when `apps/api/`, `packages/shared/`, `scripts/prepare-tuning.mjs` or
  `pnpm-lock.yaml` changed: `pnpm --filter @nearcited/api exec wrangler deploy --dry-run --outdir dist`
  (**Lint, typecheck, test, build**'s "Validate the Worker config and bundle"; after `pnpm check`,
  whose build writes the `apps/web/dist` it serves)
- repo root: `node --test scripts/sync-agents.test.mjs` and `pnpm sync:agents:check` (**Verify
  generated agent config**), fixed by `pnpm sync:agents`, committing the regenerated
  `.claude/skills/` and `.codex/agents/`
- repo root: `node --test scripts/lint-agent-neutrality.test.mjs` and `pnpm lint:agents` (**Verify
  generated agent config**)
- repo root: `node --test scripts/check-docs.test.mjs` and `node scripts/check-docs.mjs` (**Verify
  generated agent config**)

Left to CI, because each needs more than this checkout:

- **Store against Postgres and PostgREST** — needs Postgres and PostgREST. Covers
  `apps/api/src/store/`, `apps/api/test/supabase-store.integration.test.ts`, `supabase/migrations/`
  and `scripts/integration-db.sh`; with the services running and `POSTGREST_URL` set (README
  "Integration tests") it runs here as
  `pnpm --filter @nearcited/api exec vitest run test/supabase-store.integration.test.ts`.
- **End-to-end in a browser** — needs the local Supabase stack and a browser. Covers `apps/web/`,
  `apps/e2e/`, `apps/api/src/routes/`, `apps/api/src/app.ts` and `packages/shared/src/schemas.ts`;
  with the stack running and the env files written (`pnpm local:env` once) it runs here as
  `pnpm e2e`.
- CodeQL (a security alert of medium severity or higher blocks the merge, and so does any other
  alert that is an error or a warning) and the Copilot review.

The report names the CI-only suite that covers the change.

## Issue link

- **Branch pattern:** `<type>/<issue#>-<slug>`, `<type>` one of `feat`, `fix`, `refactor`, `docs`,
  `chore` (`feat/149-standing-permission`, `fix/6-stuck-scans`). Exempt work drops the number
  (`docs/dev-flow`, `chore/bump-wrangler`); Dependabot names its own. Commit subjects stay plain
  sentences.
- **Link line:** `Closes #<n>` when the branch finishes issue `n`; `Part of #<n>` for one slice of a
  spec that stays open; a slice that also finishes its own ticket names both
  (`Closes #141. Part of #202.`). One keyword per issue (`Closes #104, closes #210`). It replaces
  the template's `Closes #` first line.
- **Waiver line:** `Flow waived by the user: <reason>`, in the user's words.
- **Exempt:**
  - dependency bumps — Dependabot's pull requests, and a hand bump changing only versions in
    `package.json` files and `pnpm-lock.yaml`, with the edits it needs to pass `pnpm check`
  - changes touching only docs and agent config: the root Markdown (`README.md`, `AGENTS.md`,
    `CLAUDE.md`, `CONTRIBUTING.md`, `SECURITY.md`, `GLOSSARY.md`), `docs/`, `.agents/`, `.claude/`,
    `.codex/`, `skills-lock.json`, `.github/pull_request_template.md`
  - release prep (rare: there is no version file or changelog)
- **Defined in:** `docs/agents/dev-flow.md`.

## Hook: before PR

1. Walk the branch's whole diff (`git diff "$(git merge-base origin/main HEAD)"..HEAD`) once for
   each row of `## Rule triggers` below whose trigger it matches, and check it contains what that
   row requires. Fix what is missing; stop and tell the user when the fix is a design decision. A
   fix made here: run `docs-updater` again when it changed a documented fact, then the
   `Fast checks` from the top.
2. A migration that drops or renames something the deployed Worker uses: the body says it is
   deployed first and migrated second.
3. Fill the template: **What changed**; **How it was checked** with the fast checks actually run and
   what was left to CI; tick **Before merging** only from what step 1 and the fast checks
   established.
4. Report that CodeQL and the Copilot review also report on the PR and can block the merge.
